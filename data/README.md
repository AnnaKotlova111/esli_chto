# Данные города: формат и подключение

Всё, что зависит от города, приложение берёт из папки `data/<город>/`:
- дома и организации, которые ими управляют, их телефоны, диспетчерские, ИНН;
- телефоны городских служб;
- примеры адресов в подсказках, дата и источник данных, пометка «демо».

В коде бота и мини-приложения адресов, названий и телефонов конкретного города нет. Подключили другую папку – поменялись все ответы, карточки и подсказки.

Общими для всех городов остаются правила ответственности (58 объектов, 130 ситуаций), федеральные нормы, схемы-иллюстрации и экстренные номера 112, 104, 102.

| Папка | Что это |
|---|---|
| [`vichuga/`](vichuga/) | Пилот: 223 дома г. Вичуги и пос. Каменка, реальные открытые данные |
| [`example/`](example/) | Образец: вымышленный г. Образцовск, 8 домов, все типы организаций и все столбцы. Его удобно скопировать как шаблон. На нём CI при каждом push проверяет, что другой город подключается без правки кода |

## Как подключить город

1. Скопируйте `data/example/` в `data/<город>/`. Имя папки пишется латиницей, например `data/kineshma/`.
2. Заполните четыре файла по таблицам ниже.
3. Подключите город:
   ```bash
   npm run data:import -- data/kineshma
   ```
   Импорт напечатает число домов, организаций и служб, а также предупреждения о расхождениях в данных. При ошибке формата он остановится и напишет, какой адрес, организацию или поле нужно исправить.
4. Проверьте и соберите:
   ```bash
   npm test
   npm run build            # или docker compose up --build
   ```
5. Закоммитьте папку `data/<город>/` и пересобранный `packages/core/src/data/city.json`.

Подключённый город запоминается в `city.json` (поле `dataDir`). Поэтому `npm run data:import` без параметров и проверка в CI дальше пересобирают именно его. Вернуть пилот можно командой `npm run data:import -- data/vichuga`.

Один запуск приложения обслуживает один город: у каждого города свой справочник, свой бот и свой адрес мини-приложения.

## Файлы

| Файл | Обязателен | Что в нём |
|---|---|---|
| `meta.json` | да | Город, регион, населённые пункты, дата и источник данных, примеры адресов |
| `organizations.csv` | да | Карточки организаций: УК, ТСЖ, ЖСК, ТСН |
| `houses.csv` | да | Какой организацией управляется каждый дом |
| `services.csv` | да, для тестов | Городские службы: водоканал, теплосеть, энергосбыт и др. |

Общие правила для CSV:
- кодировка UTF-8, разделитель – запятая, первая строка – названия столбцов, как в таблицах ниже;
- поле, в котором есть запятая (адрес, список телефонов), берётся в двойные кавычки;
- пустое значение: пусто, `-` или `–`;
- порядок строк не важен.

**Телефоны** записываются в любом виде, если в номере 11 цифр и он начинается с `+7` или `8`: `+7 (493) 542-34-73`, `8 493 542 34 73`, `+7 (49354) 2-34-73`. Импорт приводит все номера к виду `+7 (493) 542-34-73`, бесплатные линии – к виду `8 (800) 350-42-12`.

### meta.json

| Поле | Обязательно | Формат | Пример (Вичуга) | Где видно |
|---|---|---|---|---|
| `city` | да | название города | `"Вичуга"` | плашка вверху мини-приложения, «О приложении», адрес «дом не выбран» |
| `region` | да | название региона | `"Ивановская область"` | не показывается; по нему из адресов убираются служебные слова |
| `idPrefix` | да | строчная латиница и цифры | `"vch"` | начало идентификатора дома в диплинках: `vch_korovina_11` |
| `settlements` | да | для каждого населённого пункта из `houses.csv`: `{ "title": "как писать в адресе", "id": "латиница или пусто" }`. У главного города `id` пустой | `"Каменка": { "title": "пос. Каменка (Вичугский район)", "id": "kamenka" }` | полный адрес дома, подсказка «В справочнике 223 дома: г. Вичуга, пос. Каменка» |
| `updatedAt` | да | дата `ГГГГ-ММ-ДД` | `"2026-09-23"` | «данные на 23.09.2026» в мини-приложении и ответах бота |
| `source` | да | откуда данные | `"Открытые данные: карточки… на mingkh.ru…"` | «О приложении», карточка выбора дома |
| `demo` | нет | `true` – данные тестовые или вымышленные | `false` | при `true`: плашка «Демо-данные: организации и телефоны вымышлены», та же пометка в ответах бота |
| `addressExamples` | нет | список из 1–4 адресов «улица номер» или населённых пунктов, каждый должен находить дом | `["Коровина 11", "Ленинградская 6", "пер. Пятницкий 13", "Каменка"]` | подсказка в поле адреса, кнопки-примеры, «например, Коровина 11» в боте. Если поля нет, примеры берутся из первых домов справочника |

### organizations.csv

Столбцы: `name,type,address,dispatch_phone,phones,houses_declared,inn,ogrn,email,site`

| Столбец | Обязательно | Формат | Пример | Где видно |
|---|---|---|---|---|
| `name` | да | полное название, короткое имя – в «ёлочках». Названия не повторяются | `Управляющая компания «Жилищно-ремонтный участок №1»` | в ответах – тип и имя в ёлочках: «УК «Жилищно-ремонтный участок №1»» |
| `type` | да | `УК`, `ТСЖ`, `ЖСК` или `ТСН` | `УК` | «Отвечает управляющая организация» или «Отвечает ТСЖ», падежи в текстах |
| `address` | нет | адрес организации | `"Ивановская обл., г. Вичуга, ул. Ленинградская, д. 22"` | текст обращения. У ТСЖ, ЖСК и ТСН по нему определяется основная организация, если дом указан за двумя |
| `dispatch_phone` | нет | телефоны аварийно-диспетчерской службы | `+7 (493) 542-34-73` | «Аварийная служба», раздел «Срочно», заявки по лифту. Если пусто, аварии принимает правление (телефоны из `phones`) |
| `phones` | да* | один или несколько через `;` | `+7 (493) 542-57-60` | кнопка «Позвонить», ответы бота |
| `houses_declared` | нет | число домов по карточке организации | `88` | не показывается; импорт сверяет его с `houses.csv` и предупреждает о расхождении |
| `inn`, `ogrn` | нет | цифры | `3701043128` | ИНН – в тексте обращения |
| `email`, `site` | нет | адрес почты, сайт без `https://` | `zru4@yandex.ru`, `zru37.ru` | карточка организации |

\* У организации должен быть хотя бы один телефон в `phones` или `dispatch_phone`, иначе импорт выдаст предупреждение.

### houses.csv

Столбцы: `address,organization`

| Столбец | Обязательно | Формат | Пример |
|---|---|---|---|
| `address` | да | ровно три части через запятую: `улица, номер, населённый пункт`. Тип улицы – `ул.`, `пер.`, `пр-т`, `просп.`, `пл.`, `проезд`, `б-р`, `ш.` (до или после названия). Населённый пункт – как в `settlements` | `"ул. Коровина, 11, Вичуга"`, `"Пятницкий пер., 13, Вичуга"`, `"ул. Николаева, 5, Каменка"` |
| `organization` | да | точно как `name` в `organizations.csv` | `Управляющая компания «Жилищно-ремонтный участок №1»` |

Из адреса собирается идентификатор дома: `idPrefix`, `id` населённого пункта, улица и номер латиницей, например `vch_kamenka_nikolaeva_5`. Он попадает в диплинки из бота, поэтому после запуска адреса домов лучше не переименовывать.

Если один адрес указан за двумя организациями, основной считается ТСЖ, ЖСК или ТСН, чей собственный адрес – этот дом. Вторая организация показывается у дома с советом уточнить по квитанции.

### services.csv

Столбцы: `party,name,phones,hours,address,email,site,note`

| Столбец | Обязательно | Формат | Пример |
|---|---|---|---|
| `party` | да | код службы из таблицы ниже, каждый не больше одного раза | `water_utility` |
| `name` | да | название | `«Городской водопровод» (г. Вичуга)` |
| `phones` | да* | `подпись:номер; подпись:номер` | `Диспетчерская:+7 (493) 542-44-72; Приёмная:+7 (493) 542-23-46` |
| `hours`, `address`, `email`, `site` | нет | как в карточке | `пн–пт 8:00-17:00` |
| `note` | нет | пояснение для жителя | `Ваша компания указана в квитанции за свет.` |

| `party` | Служба | Без телефона |
|---|---|---|
| `water_utility` | водоснабжение и водоотведение | нельзя* |
| `heat_utility` | теплоснабжение | нельзя* |
| `energy_utility` | энергосбыт или сетевая компания | нельзя* |
| `gas_service` | газовая служба (обслуживание, справки; при запахе газа всегда 104) | нельзя* |
| `tko_operator` | региональный оператор по вывозу мусора | нельзя* |
| `municipality` | администрация (ЕДДС) | нельзя* |
| `housing_inspection` | государственная жилищная инспекция | нельзя* |
| `lift_service` | лифтовая организация | можно: заявки по лифту принимает диспетчерская или правление дома, жителю показывается `note` |
| `intercom_service` | обслуживание домофона | можно: показывается только `note`, например «телефон – на панели домофона» (импорт предупредит) |

\* Семь служб без пометки «можно» нужны тестам. Без их телефонов часть ответов останется без номера, и `npm test` это покажет.

## Что проверяет импорт

**Ошибки** – импорт останавливается и пишет, что именно исправить:
- нет обязательного файла или поля `meta.json`, неверный `idPrefix` или дата;
- неизвестный тип организации, повторяются названия организаций;
- дом ссылается на организацию, которой нет в `organizations.csv`;
- адрес не из трёх частей, населённый пункт не описан в `settlements`;
- телефон не из 11 цифр;
- совпали идентификаторы домов, неизвестный код службы или служба указана дважды.

**Предупреждения** – импорт продолжает и сохраняет их в `city.json`:
- дом указан за несколькими организациями;
- у организации нет домов или телефонов;
- число домов не совпадает с `houses_declared`;
- у службы нет телефона.

## Что нужно для тестов

`npm test` и интеграционный тест проходят на справочнике любого города, если в нём есть:
- хотя бы один дом УК с `dispatch_phone`;
- хотя бы один дом ТСЖ, ЖСК или ТСН без `dispatch_phone`;
- телефоны семи обязательных служб из `services.csv`;
- примеры `addressExamples`, каждый из которых находит дом.

Проверки конкретных домов, организаций и телефонов Вичуги выполняются, только когда подключена Вичуга. Для другого города они пропускаются.
