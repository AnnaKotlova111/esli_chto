# Масштабирование и пилот

## Ядро и переменная часть

| Ядро: одинаково для всей России | Переменная часть: своя для города и дома |
|---|---|
| Правила ответственности: 58 объектов, 130 ситуаций, вопросы и выводы | Справочник домов: адрес → управляющая организация |
| Справочник федеральных норм (ЖК, ГК, ПП № 491, 354, 290, 410, 958, 293, 1309, 1479, 131-ФЗ) | Контакты организаций: телефоны, диспетчерская, e-mail, ИНН |
| Схемы-иллюстрации и интерфейс | Контакты городских служб: водоканал, теплосеть, ТКО, администрация, ГЖИ |
| Экстренные номера 112, 104, 102 | Региональные нормы: законы о тишине, правила благоустройства |
| Бот, шаблоны обращений, поиск | Особенности конкретного дома: лифт, газ, мусоропровод |

При переходе в другой город ядро не меняется. Переменная часть подключается данными, код править не нужно.

## Как подключить другой город

Формат всех файлов, столбцы, примеры и места, где каждое поле видно в интерфейсе, описаны в [data/README.md](../data/README.md).

1. Скопировать образец `data/example/` (вымышленный г. Образцовск) в `data/<город>/` и заполнить четыре файла:
   - `meta.json`: город, регион, населённые пункты, префикс идентификаторов, дата, источник, примеры адресов для подсказок. Если реальных данных пока нет и справочник заполнен тестовыми, туда же записывается `"demo": true`. Тогда мини-приложение и бот сами показывают пометку «Демо-данные: организации и телефоны вымышлены»;
   - `organizations.csv`: карточки организаций – тип (УК, ТСЖ, ЖСК, ТСН), телефоны, диспетчерская, ИНН, e-mail, сайт;
   - `houses.csv`: адрес «улица, номер, населённый пункт» → организация;
   - `services.csv`: городские службы – водоканал, теплосеть, энергосбыт, газ, оператор ТКО, администрация, ГЖИ, лифт, домофон.
2. Выполнить `npm run data:import -- data/<город>`. Скрипт проверит данные, напечатает расхождения (дубли адресов, организации без домов, несовпадение числа домов) и запомнит подключённый город.
3. Выполнить `npm test`. Общие тесты проверят данные нового города: у каждого дома есть организация с телефоном, идентификаторы годятся для диплинков, примеры адресов находят дома, все ответы строятся без ошибок. Проверки конкретных домов Вичуги для другого города пропускаются.
4. Собрать проект (`npm run build` или `docker compose up --build`). Справочник попадёт в мини-приложение и в бота: названия организаций, телефоны, адреса и подсказки с примерами адресов меняются вместе с данными, код править не нужно.

Что подключение другого города работает без правки кода, проверяет CI при каждом push: он подключает образец `data/example/` и прогоняет проверку типов, все тесты, сборку и интеграционный тест бота.

Один запуск приложения обслуживает один город. Для второго города нужен свой запуск: свой бот в MAX и свой адрес мини-приложения. Несколько городов в одном боте – шаг следующей версии.

Данные для любого города берутся из тех же открытых реестров: ГИС ЖКХ (раздел «Реестр объектов жилищного фонда»), карточек управляющих организаций, сведений региональной жилищной инспекции. Второй город запускается работой с таблицей, без разработки.

## Риски и допущения

- Данные устаревают: организации меняют телефоны и договоры управления. Поэтому на экране указана дата сведений и совет сверяться с квитанцией, таблицы обновляются раз в месяц, а в перспективе появится кабинет УК.
- Источник бывает противоречив: дом может числиться за двумя организациями. Импорт не исправляет такое молча, приложение показывает обе.
- Правила не заменяют консультацию юриста. Спорные случаи помечены, у каждого вывода есть норма и шаблон письменного обращения.
- Нагрузка. Мини-приложение состоит из статических файлов, бот работает одним процессом Node.js. Для города размера Вичуги хватает минимального сервера, дальше возможно горизонтальное масштабирование с общим хранилищем выбранных домов.
