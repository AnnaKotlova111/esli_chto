# «Если что»: кто отвечает, куда звонить и что делать, если в доме что-то сломалось

Мини-приложение и чат-бот в MAX для жителей многоквартирных домов. Житель нажимает на предмет на картинке дома или квартиры или описывает проблему словами. В ответ он узнаёт, кто отвечает, получает телефон своей организации, шаги и норму, на которую можно сослаться. Спорные случаи помечены, и для них готов текст обращения.

Пилотный город: Вичуга (Ивановская область). В справочнике 223 дома и 19 управляющих организаций, ТСЖ, ЖСК и ТСН из открытых данных. Правила ответственности федеральные и подходят для любого города.

> Сведения о домах и организациях взяты из открытых источников на 23.09.2026 (см. [docs/DATA.md](docs/DATA.md)). Там же подключены контакты городских служб Вичуги: водоснабжение, теплоснабжение, энергосбыт, газ, ТКО, администрация, ГЖИ. Это справочная информация, а не юридическая консультация.

## 1. Назначение

Житель замечает поломку (течёт кран, не горит лампочка в подъезде, не работает лифт) и не знает, кто за неё отвечает: управляющая организация, ресурсоснабжающая организация или он сам. В нормах граница ответственности описана через элементы, которые не различишь на глаз: «первое отключающее устройство», «квартирный прибор учёта». Контакты разбросаны по квитанциям и доскам объявлений. В итоге люди звонят не туда и получают отказы.

«Если что» решает одну задачу: быстро определить, кто отвечает, и дать одно понятное действие, кнопку «Позвонить». Для каждого предмета и ситуации заранее записаны уточняющие вопросы и вывод со ссылкой на норму. Приложение проходит эту цепочку по ответам жителя, поэтому на один и тот же вопрос в одном доме ответ всегда одинаковый и его можно проверить. Подробнее о проблеме и границах MVP в [docs/PROBLEM.md](docs/PROBLEM.md).

## 2. Основной пользовательский сценарий

### В мини-приложении

1. Открыть бота в MAX и нажать «Открыть карту дома».
2. «Выберите свой дом» → ввести адрес («Коровина 11») → появится карточка дома с организацией и телефонами. По желанию отметить, есть ли в доме лифт, газ, мусоропровод.
3. Выбрать вкладку «Наш дом» (схемы «Снаружи», «Подъезд», «Подвал и сети») или «Моя квартира» (план квартиры) и нажать на подпись объекта на картинке. Можно вместо этого написать в строке «Что случилось?», например «течёт кран».
4. Выбрать ситуацию и при необходимости ответить на 1-2 вопроса.
5. Получить ответ: блок «Срочно» с кнопкой звонка (если нужно), кто отвечает и «Позвонить», почему так, что делать и на чём основан ответ.
6. В спорном случае или когда нужен письменный запрос, нажать «Составить обращение». Адрес дома, организация с ИНН и дата уже подставлены, текст можно поправить, скопировать или отправить в чат.

Отдельная кнопка «Срочно» внизу собирает все опасные и аварийные ситуации с прямым звонком: 112, 104 и аварийная служба дома.

### В боте

Написать «течёт кран» → выбрать ситуацию кнопкой → получить короткий ответ (кто отвечает, телефон, шаги, норма) → «Подробнее в приложении» откроет ту же ситуацию. Свой дом выбирается командой `/house Коровина 11`.

## 3. Состав и архитектура

Монорепозиторий на npm workspaces:

| Пакет | Роль |
|---|---|
| `packages/core` | Ядро: типы, правила ответственности (58 объектов, 130 ситуаций), справочник норм (52), справочник домов города, движок вопросов, поиск ситуаций и домов, шаблоны обращений, диплинки. Общее для бота и мини-приложения, поэтому ответы не расходятся. |
| `apps/webapp` | Мини-приложение: React 19, официальный UI-кит MAX, MAX Bridge. Схемы-иллюстрации, карточки, вопросы, поиск, конструктор обращения. Работает без собственного API, всё собрано в статические файлы. |
| `apps/bot` | Бот на официальной библиотеке MAX Bot API: разбор свободного текста, диалог кнопками, выбор дома по адресу, открытие мини-приложения по диплинку. Этот же процесс раздаёт статику мини-приложения и отвечает на `/healthz`. |
| `data/vichuga` | Исходные таблицы домов и организаций города (CSV), из них собирается справочник. |
| `tools`, `scripts` | Инструменты разработки: расчёт зон нажатия по пикселям иллюстраций, импорт домов, сборка документации из данных. В образ не попадают. |

```
┌─────────────── MAX (мобильная / веб / десктоп) ────────────────┐
│  чат с ботом ── кнопка «Открыть карту дома» (диплинк) ──► мини-приложение │
└───────┬────────────────────────────────────────────┬──────────┘
        │ Bot API (вебхук / long polling)             │ HTTPS
        ▼                                             ▼
┌──────────────────── один контейнер (Node.js) ─────────────────────┐
│ apps/bot      бот + раздача статики + /healthz                      │
│ apps/webapp   собранная статика (без сервера данных)                │
│ packages/core правила, нормы, справочник домов Вичуги               │
└──────────────────────────────────────────────────────────────────┘
```

Собственного HTTP API с пользовательскими данными нет: мини-приложение состоит из статических файлов, бот работает поверх Bot API. Поэтому OpenAPI и `DATA-API.yaml` не требуются.

## 4. Запуск одной командой

Нужен Docker с Compose v2. Из корня репозитория:

```bash
docker compose up --build
```

Файл `.env` для этого не нужен, у всех переменных есть значения по умолчанию. Он понадобится, чтобы включить бота: `cp .env.example .env` и вписать токен (см. ниже).

Откройте <http://localhost:8080>. Мини-приложение работает сразу, бот без токена выключен. Проверка состояния: <http://localhost:8080/healthz> возвращает
`{"ok":true,"app":"Если что","version":"1.0.0","bot":"disabled","houses":223,"elements":58,"situations":130}`.

Значения поля `bot`:

- `disabled`: токена нет;
- `connecting`: идёт подключение к MAX;
- `polling` или `webhook`: бот работает;
- `error`: API MAX недоступен (сеть, сбой платформы, неверный токен). Сервер при этом не останавливается, мини-приложение продолжает работать, а подключение повторяется через 5, 10, 20… секунд, но не реже раза в минуту. Причина пишется в журнал.

В образ попадают только собранные файлы (multi-stage сборка на `node:24-alpine`). Сборку и запуск контейнера с проверкой `/healthz` выполняет CI при каждом изменении.

### С ботом

1. Впишите в `.env` токен: `BOT_TOKEN=…`. В хакатоне его выдают организаторы, вне хакатона бота создают в business.max.ru → «Чат-боты».
2. Для разработки оставьте `PUBLIC_URL` пустым, тогда бот работает через long polling.
3. Для рабочего запуска нужен публичный HTTPS-адрес, потому что вебхук и мини-приложение работают только по HTTPS:
   ```bash
   # в .env: DOMAIN=esli-chto.example.org и PUBLIC_URL=https://esli-chto.example.org
   docker compose --profile https up -d --build
   ```
   Caddy получит сертификат автоматически. Домен должен указывать на сервер, порты 80 и 443 должны быть открыты. Секрет вебхука задаётся в `WEBHOOK_SECRET`, а если он пуст, генерируется при запуске.
4. Подключите мини-приложение к боту: business.max.ru → чат-бот → ⋮ → «Настройки» → адрес мини-приложения. В хакатоне адрес передаётся организаторам через форму, и они привязывают его к боту.

### Предпросмотр мини-приложения

`.github/workflows/pages.yml` при каждом изменении ветки `main` собирает `apps/webapp` и публикует статику на GitHub Pages (Settings → Pages → Source: GitHub Actions). Бот при этом запускается отдельно и должен работать постоянно.

## 5. Переменные окружения

| Переменная | Обязательна | По умолчанию | Где действует | Назначение |
|---|---|---|---|---|
| `BOT_TOKEN` | нет | не задан | Docker и `npm start` | Токен бота. Без него запускается только мини-приложение. Не коммитить. |
| `BOT_USERNAME` | нет | из ответа MAX `/me` | Docker и `npm start` | Ник бота для кнопок открытия мини-приложения |
| `PUBLIC_URL` | нет | не задан | Docker и `npm start` | Публичный `https://…`. Если задан, бот работает через вебхук, если пуст, через long polling |
| `WEBHOOK_SECRET` | нет | случайный при запуске | Docker и `npm start` | Секрет, который MAX присылает в заголовке каждого события: 5-256 символов, латиница, цифры, `_` и `-`. Значение другого формата не используется: сервер пишет предупреждение и генерирует секрет сам |
| `WEBHOOK_PATH` | нет | `/max/webhook` | Docker и `npm start` | Путь вебхука |
| `RATE_LIMIT_PER_MINUTE` | нет | `20` | Docker и `npm start` | Сколько событий в минуту обрабатывается от одного пользователя |
| `MAX_API_TIMEOUT_MS` | нет | `60000` | Docker и `npm start` | Сколько ждать ответа MAX API. Зависший запрос прерывается, пользователь получает сообщение об ошибке |
| `APP_PORT` | нет | `8080` | только Docker (`compose.yaml`) | Порт на хосте |
| `DOMAIN` | для профиля `https` | не задан | только Docker | Домен для Caddy |
| `PORT` | нет | `8080` | только `npm start` | Порт сервера. В контейнере всегда `8080`, наружу пробрасывается `APP_PORT` |
| `WEBAPP_DIST` | нет | `apps/webapp/dist`, в образе `/app/webapp` | только `npm start` | Каталог собранного мини-приложения |
| `MAX_API_BASE_URL` | нет | не задан | только тесты | Адрес имитации MAX API (`apps/bot/test/integration.mjs`) |

`.env.example` не содержит рабочих значений, `.env` исключён из git и из Docker-образа. Рабочий токен для проверки передаётся организаторам на служебном первом слайде презентации.

## 7. Зависимости

Версии зафиксированы в `package-lock.json` (один lock-файл на монорепозиторий, установка через `npm ci`). У всех зависимостей открытые лицензии.

- Node.js 20.19 или новее (образ собран на `node:24-alpine`, актуальной LTS-версии).
- Мини-приложение: `react` и `react-dom` 19.2.8 (эту версию требует UI-кит), `@maxhub/max-ui` 0.5.0 (MIT), `lucide-react` для иконок (ISC), `@fontsource/inter` для шрифта (OFL), Vite.
- Бот: `@maxhub/max-bot-api` 0.3.1 (MIT), сборка esbuild в один файл.
- Тесты и проверка типов: Vitest, jsdom, TypeScript.
- `tools/` (отдельный `package.json`, в образ не входит): `sharp` для чтения пикселей иллюстраций при расчёте зон нажатия.
- Скрипт MAX Bridge (`https://st.max.ru/js/max-web-app.js`) подключается с CDN платформы. Вне MAX приложение работает без него.

## 8. Внешние сервисы и интеграции

| Сервис | Зачем | Можно ли поднять в Docker |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | сообщения бота | Нет, это сам мессенджер, нужен токен. Для автотестов есть имитация API (`apps/bot/test/integration.mjs`). |
| MAX Bridge (`st.max.ru`) | нативные функции мини-приложения | Нет. Вне MAX работают запасные варианты. |
| Корневой сертификат Минцифры | API MAX подписан центром «Russian Trusted Root CA», которого нет в хранилищах Node.js и образа. Публичный сертификат (`deploy/russian_trusted_root_ca.pem`) встраивается в сборку бота и используется только для запросов к API MAX. | Уже учтено |
| Публичный домен и HTTPS | требование MAX к мини-приложению и вебхуку | Сертификат выпускает Caddy (профиль `https`), домен нужен свой |

Возможности MAX, которые использует мини-приложение:

- нативная кнопка «Назад», которая закрывает шаги по одному;
- тактильный отклик при выборе, успехе и опасности;
- хранилище устройства для дома, отметок и истории, с запасным вариантом вне MAX и ограничением времени ожидания, чтобы экран не зависал;
- запрос контакта: номер телефона в обращение одной кнопкой;
- нативная отправка ответа или обращения в чат;
- открытие внешней ссылки на первоисточник нормы;
- подтверждение закрытия, если в черновике обращения есть несохранённые правки;
- параметр запуска: диплинк из бота сразу открывает нужную ситуацию дома.

Интеграций с ГИС ЖКХ и системами управляющих организаций нет. Справочник домов представляет собой снимок открытых данных на дату, указанную на экране. Заявки приложение не принимает, а готовит текст, который житель отправляет сам.

## 9. Работа с данными

Подробно в [docs/DATA.md](docs/DATA.md).

- Правила лежат в `packages/core/src/data/elements-*.ts`: объект → ситуации → ответ или уточняющий вопрос. У ответа указаны ответственные, однозначность (`clear` / `disputed`), основание (`norm` / `practice` / `contract`), пояснение, шаги, нормы и тип обращения. Ответ с основанием «практика» или «договор» всегда помечен как спорный случай и сопровождается шаблоном обращения, это проверяет тест.
- Нормы лежат в `packages/core/src/data/norms.ts` и пересказаны своими словами. 50 из 52 сверены по пунктам в действующей редакции, журнал сверки в [docs/NORMS.md](docs/NORMS.md).
- Дома и организации: `data/vichuga/*.csv` → `npm run data:import` → `packages/core/src/data/city.json`. Импорт проверяет данные и печатает расхождения источника.
- Персональные данные (ФИО, квартира, телефон для обращения, выбранный дом, отметки о доме) хранятся только на устройстве пользователя: в хранилище MAX, а вне MAX в хранилище браузера под ключами с префиксом `esli_chto:`. Префикс не даёт другим сайтам того же домена (например, другим проектам на `github.io`) прочитать или затереть эти данные. Длина полей обращения ограничена: ФИО до 120 символов, подъезд и квартира до 10, телефон до 20.
- Бот держит в памяти процесса только выбранный дом, счётчик запросов и отметку «ждёт адрес» после `/house`. Команда `/forget` удаляет всё это. Тексты сообщений не сохраняются. Дом из диплинка («Начать» по ссылке с домом) запоминается так же, как выбранный командой `/house`.
- Другой город подключается таблицами в `data/<город>/` без правки кода. Если реальных данных ещё нет и справочник тестовый, в `meta.json` ставится `"demo": true`, и тогда мини-приложение и бот сами помечают данные как демонстрационные (см. [docs/SCALING.md](docs/SCALING.md)).

## 11. Пошаговая проверка

### A. Мини-приложение без MAX (2 минуты)

1. `docker compose up --build` → <http://localhost:8080> (удобно в режиме телефона в инструментах разработчика) или сразу предпросмотр <https://annakotlova111.github.io/esli_chto/>.
2. «Выберите свой дом» → «Коровина 11». Появится карточка: УК «Жилищно-ремонтный участок №1», телефоны, диспетчерская. Снимите отметку «Лифт» и нажмите «Готово».
3. На схеме «Снаружи» подпись «Лифт» приглушена и помечена «нет в доме». Нажмите «Крыша» → «Течёт с крыши в квартиру или подъезд». В ответе будет пометка «Срочно», аварийная служба с кнопкой «Позвонить», пояснение, шаги и нормы.
4. Нажмите «Составить обращение»: в тексте уже есть адрес дома, УК с ИНН и дата. Введите в поле «Телефон» `12345`, и под полем появится подсказка «номер неполный». Нажмите «Отправить в чат»: приложение предупредит, что в тексте остались места в [квадратных скобках]. «Заполнить» переведёт к пустому полю ФИО, «Отправить всё равно» отправит текст как есть.
5. «Моя квартира» → «Газовая плита» → «Запах газа»: красный блок «Опасно» и кнопка «Позвонить 104».
6. Внизу «Срочно»: 112 и 104, список опасных ситуаций с прямым звонком, аварии в доме.
7. В строке «Что случилось?» напишите «засор»: появятся ситуации из разных объектов.

### B. Бот и мини-приложение в MAX

1. Откройте [@t527_hakaton_max_bot](https://max.ru/t527_hakaton_max_bot) или запустите свою копию с `BOT_TOKEN` и HTTPS (раздел 4) и подключите к ней мини-приложение.
2. «Начать» → приветствие. `/house Коровина 11`: бот запомнит дом и покажет телефоны УК.
3. «течёт кран» → кнопка ситуации → короткий ответ → «Подробнее в приложении» откроет ту же ситуацию того же дома (проверьте на телефоне и в веб-версии MAX).
4. `/urgent` показывает 112, 104, 102 и аварийную службу дома, `/houses` показывает список домов по страницам, `/forget` стирает выбранный дом.

| Боту: «Привет», «Здравствуйте», «Начать» | Рассказ о боте и мини-приложении: для чего они, как начать, выбор дома, 112 и 104 |
| Боту: «Здравствуйте, течёт кран» | Приветствие пропускается, сразу варианты ситуаций |

| «‹ Назад» под вопросом или ответом бота | Шаг назад: к прошлому вопросу, а с первого шага к ситуациям объекта |
| Боту: «абракадабра» | «Не нашёл» и кнопки «Найти на схеме» и «Срочно», без тупика |
| Боту: фото, стикер или файл без текста | «Я понимаю только текст…» и кнопки «Открыть карту дома» и «Срочно» |
| Сообщение боту в групповом чате | Бот молчит |
| «Начать» по ссылке с домом (`start=h_vch_pyatnitskiy_13`) | Карточка ТСЖ «Старатели», дальше бот отвечает с телефонами этого дома |
| Обращение с незаполненными [полями] → «Отправить в чат» | Предупреждение «Остались незаполненные поля»: «Заполнить» или «Отправить всё равно» |

| API MAX не ответил на отправку сообщения | Через `MAX_API_TIMEOUT_MS` запрос прерывается, пользователь получает «Что-то пошло не так. Попробуйте ещё раз…» |

## 13. Известные ограничения

- Справочник составлен по открытым данным на 23.09.2026. Организации могут сменить телефоны или договоры управления, поэтому на экране и в ответах бота указана дата и совет сверяться с квитанцией.
- Телефона домофонной компании нет: в городе их несколько, и открытые данные не говорят, какая обслуживает дом. Карточка подсказывает, что телефон указан на панели домофона или в квитанции. Лифтовой организации в городе нет, заявки по лифту принимает диспетчерская УК дома.
- В Вичуге две энергосбытовые компании. Показываются обе с пояснением, что своя указана в квитанции.
- Нет сведений об этажности и оборудовании домов, поэтому по умолчанию показываются все объекты, а лишнее житель отмечает сам.
- Расхождения источника: ул. Московская, 13 указана за двумя организациями, у ЖСК «Ногинец-4» в источнике нет номера дома, и в справочник он не попал.
- Выводы опираются на нормы и типовую практику, но договор управления конкретного дома может менять границы. Две ссылки (региональные законы о тишине и ПДД во дворах) указаны на уровне документа, и выводы по ним помечены как спорные.
- Бот хранит выбранный дом в памяти процесса, после перезапуска его нужно выбрать снова. В мини-приложении выбор хранится на устройстве.
- Нативные функции MAX проверены в мобильном клиенте 29.09.2026: открытие из бота, хранение выбранного дома, кнопка «Назад», номер из профиля MAX после разрешения, отправка через системное меню «Поделиться». Тактильный отклик работает на Android, на iPhone он не ощущается. В веб-версии MAX часть функций недоступна, и работают запасные варианты: хранилище браузера, копирование текста, ввод номера вручную.
- Иллюстрации плотные, на телефоне подписи мелкие. Поэтому есть кнопка «Крупнее» и полный список объектов под схемой.

## 14. Остановка и повторный запуск

```bash
docker compose down              # остановить и удалить контейнеры
docker compose up -d --build     # запустить снова в фоне
docker compose logs -f app       # журнал (JSON-строки)
```

Состояния на сервере нет, поэтому перезапуск безопасен: бот только забудет выбранные дома (см. раздел 13). После изменения `.env` выполните `docker compose up -d`. Остановить только HTTPS-прокси: `docker compose --profile https stop caddy`.

## 15. Разработка и тесты

```bash
npm ci
npm run dev:web          # мини-приложение на http://localhost:5173
npm run dev:bot          # собрать и запустить бота с .env из корня; статику отдаёт из apps/webapp/dist (после npm run build)
npm run build            # сборка мини-приложения и бота
npm start                # запуск собранного сервера
npm run data:import      # пересобрать справочник домов из data/vichuga/*.csv
npm run docs             # опись схем, журнал норм, политика и условия из данных
npm ci --prefix tools && npm run scenes:detect   # пересчитать зоны нажатия по иллюстрациям
```

Чтобы добавить ситуацию, допишите данные в `packages/core/src/data/elements-*.ts`. Тесты проверят нормы, шаги, пометки спорности, экстренные номера и диплинки, а обход интерфейса откроет каждую ветку. Чтобы подключить другой город, положите таблицы в `data/<город>/` и выполните импорт.
