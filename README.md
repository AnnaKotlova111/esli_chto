# «Если что»: кто отвечает, куда звонить и что делать, если в доме что-то сломалось

Мини-приложение и чат-бот в MAX для жителей многоквартирных домов. Житель нажимает на предмет на картинке дома или квартиры или описывает проблему словами. В ответ он узнаёт, кто отвечает, получает телефон своей организации, шаги и норму, на которую можно сослаться. Спорные случаи помечены, и для них готов текст обращения.

Пилотный город: Вичуга (Ивановская область). В справочнике 223 дома (г. Вичуга и пос. Каменка Вичугского района) и 19 организаций, которые ими управляют: 4 УК, 6 ТСЖ, 8 ЖСК и 1 ТСН. Правила ответственности опираются на федеральные нормы и подходят для любого города. Исключение составляют региональные законы о тишине: на них ссылаются только ответы, помеченные как спорные (раздел 13).

> Сведения о домах и организациях взяты из открытых источников на 23.09.2026 (см. [docs/DATA.md](docs/DATA.md)). Там же подключены контакты городских служб Вичуги: водоснабжение, теплоснабжение, энергосбыт, газ, ТКО, администрация, ГЖИ. Данные реальные, не демонстрационные: пометка «Демо-данные» в интерфейсе не показывается (как её включить для тестового города, см. раздел 9). Это справочная информация, а не юридическая консультация.

## 1. Назначение

Житель замечает поломку (течёт кран, не горит лампочка в подъезде, не работает лифт) и не знает, кто за неё отвечает: управляющая организация, ресурсоснабжающая организация или он сам. В нормах граница ответственности описана через элементы, которые не различишь на глаз: «первое отключающее устройство», «квартирный прибор учёта». Контакты разбросаны по квитанциям и доскам объявлений. В итоге люди звонят не туда и получают отказы.

«Если что» решает одну задачу: быстро определить, кто отвечает, и дать одно понятное действие, кнопку «Позвонить». Для каждого предмета и ситуации заранее записаны уточняющие вопросы и вывод со ссылкой на норму. Приложение проходит эту цепочку по ответам жителя, поэтому на один и тот же вопрос в одном доме ответ всегда одинаковый и его можно проверить. Подробнее о проблеме и границах MVP в [docs/PROBLEM.md](docs/PROBLEM.md).

## 2. Основной пользовательский сценарий

### В мини-приложении

1. Открыть бота в MAX и нажать «Открыть карту дома».
2. «Выберите свой дом» → ввести адрес («Коровина 11») → появится карточка дома с организацией и телефонами. По желанию отметить, есть ли в доме лифт, газ, мусоропровод.
3. Выбрать вкладку «Наш дом» (схемы «Снаружи», «Подъезд», «Подвал и сети») или «Моя квартира» (план квартиры) и нажать на подпись объекта на картинке. Можно вместо этого написать в строке «Что случилось?», например «течёт кран».
4. Выбрать ситуацию и при необходимости ответить на 1-2 вопроса.
5. Получить ответ: блок «Срочно» с кнопкой звонка (если нужно), кто отвечает и «Позвонить», почему так, что делать и на чём основан ответ.
6. В спорном случае или когда нужен письменный запрос, нажать «Составить обращение». Адрес дома, название организации (у управляющих компаний и ИНН) и дата уже подставлены, текст можно поправить, скопировать или отправить в чат.

Отдельная кнопка «Срочно» внизу собирает все опасные и аварийные ситуации с прямым звонком: 112, 104 и аварийная служба дома.

### В боте

Написать «течёт кран» → выбрать ситуацию кнопкой → получить короткий ответ (кто отвечает, телефон, шаги; нормы и пояснение показываются в приложении) → «Подробнее в приложении» (или «Подробнее и шаблон обращения», если для ситуации есть шаблон) откроет ту же ситуацию. Свой дом выбирается командой `/house Коровина 11`.

## 4. Запуск одной командой

Нужен Docker с Compose v2. Из корня репозитория:

```bash
docker compose up --build
```

Файл `.env` для этого не нужен, у всех переменных есть значения по умолчанию. Он понадобится, чтобы включить бота: `cp .env.example .env` и вписать токен (см. ниже).

Сборка образа занимает не больше 5 минут без учёта загрузки базовых образов `node:24-alpine`. Этот предел задан в CI (`timeout-minutes: 5`), при превышении проверка падает.

Откройте <http://localhost:8080>. Мини-приложение работает сразу, бот без токена выключен. Проверка состояния: <http://localhost:8080/healthz> возвращает
`{"ok":true,"app":"Если что","version":"1.0.0","bot":"disabled","houses":223,"elements":58,"situations":130}`.

Значения поля `bot`:

- `disabled`: токена нет;
- `connecting`: идёт подключение к MAX;
- `polling` или `webhook`: бот работает;
- `error`: API MAX недоступен (сеть, сбой платформы, неверный токен). Сервер при этом не останавливается, мини-приложение продолжает работать, а подключение повторяется через 5, 10, 20… секунд, но не реже раза в минуту. Причина пишется в журнал.
- `conflict`: у бота с этим токеном уже есть вебхук, то есть его обслуживает другой сервер в режиме вебхука. Long polling не запущен, чтобы не отключить тот сервер (см. «С ботом»). Мини-приложение работает.

В образ попадают только собранные файлы (multi-stage сборка на `node:24-alpine`). Сборку и запуск контейнера с проверкой `/healthz` выполняет CI на GitHub при каждом push и pull request.

### С ботом

Бот поддерживает два режима получения событий от MAX:

- **long polling** (`PUBLIC_URL` пуст) – бот сам запрашивает новые события, публичный адрес для него не нужен. В этом режиме работает рабочий бот @t527_hakaton_max_bot;
- **вебхук** (`PUBLIC_URL` задан) – MAX присылает события на публичный HTTPS-адрес сервера. Режим поддерживается кодом и проверен интеграционным тестом на имитации MAX API (`npm run test:integration`), но в рабочем развёртывании не используется.

**Важно для проверки.** Для локального запуска используйте токен своего бота, а не рабочего @t527_hakaton_max_bot:

- рабочий бот работает через long polling, и копия с тем же токеном в том же режиме будет забирать события из той же очереди. Часть сообщений обработает рабочий бот, часть – ваша копия. Обнаружить второй экземпляр в этом режиме нельзя;
- если запустить копию с тем же токеном в режиме вебхука (задать `PUBLIC_URL`), MAX начнёт отправлять события на вебхук, и рабочий бот перестанет их получать.

Для развёртываний в режиме вебхука есть защита: при старте long polling библиотека бота снимает все подписки на вебхук, поэтому сервер сначала проверяет подписки. Если вебхук уже есть, long polling не запускается, в журнал пишется причина, а `/healthz` показывает `"bot":"conflict"`. Переменная `FORCE_POLLING=1` отменяет эту проверку и снимает вебхук.

1. Впишите в `.env` токен: `BOT_TOKEN=…`. Вне хакатона бота создают в business.max.ru → «Чат-боты».
2. Оставьте `PUBLIC_URL` пустым, тогда бот работает через long polling, как рабочий бот. Этого достаточно и для разработки, и для постоянной работы.
3. Режим вебхука (по желанию). Нужен публичный HTTPS-адрес, потому что MAX присылает события только по HTTPS:
   ```bash
   # в .env: DOMAIN=esli-chto.example.org и PUBLIC_URL=https://esli-chto.example.org
   docker compose --profile https up -d --build
   ```
   Caddy получит сертификат автоматически. Домен должен указывать на сервер, порты 80 и 443 должны быть открыты. Секрет вебхука задаётся в `WEBHOOK_SECRET`, а если он пуст, генерируется при запуске.
4. Подключите мини-приложение к боту: business.max.ru → чат-бот → ⋮ → «Настройки» → адрес мини-приложения. MAX открывает мини-приложение только по HTTPS: подойдёт предпросмотр на GitHub Pages (см. ниже) или свой домен с профилем `https`. В хакатоне адрес передаётся организаторам через форму, и они привязывают его к боту. Кнопка «Открыть карту дома» открывает адрес, привязанный к боту в MAX, а не `localhost`. Поэтому при локальном запуске бот отвечает с вашего компьютера, а мини-приложение по-прежнему открывается с привязанного адреса.

### Предпросмотр мини-приложения

`.github/workflows/pages.yml` при каждом изменении ветки `main` собирает `apps/webapp` и публикует статику на GitHub Pages (Settings → Pages → Source: GitHub Actions). Бот при этом запускается отдельно и должен работать постоянно.

## 5. Переменные окружения

| Переменная | Обязательна | По умолчанию | Где действует | Назначение |
|---|---|---|---|---|
| `BOT_TOKEN` | нет | не задан | Docker и `npm start` | Токен бота. Без него запускается только мини-приложение. Не коммитить. |
| `BOT_USERNAME` | нет | из ответа MAX `/me` | Docker и `npm start` | Ник бота для кнопок открытия мини-приложения |
| `PUBLIC_URL` | нет | не задан | Docker и `npm start` | Публичный `https://…`. Если задан, бот работает через вебхук, если пуст, через long polling. Рабочий бот работает с пустым значением |
| `WEBHOOK_SECRET` | нет | случайный при запуске | Docker и `npm start` | Секрет, который MAX присылает в заголовке каждого события: 5-256 символов, латиница, цифры, `_` и `-`. Значение другого формата не используется: сервер пишет предупреждение и генерирует секрет сам |
| `WEBHOOK_PATH` | нет | `/max/webhook` | Docker и `npm start` | Путь вебхука |
| `RATE_LIMIT_PER_MINUTE` | нет | `20` | Docker и `npm start` | Сколько событий в минуту обрабатывается от одного пользователя |
| `MAX_API_TIMEOUT_MS` | нет | `60000` | Docker и `npm start` | Сколько ждать ответа MAX API. Зависший запрос прерывается, пользователь получает сообщение об ошибке |
| `FORCE_POLLING` | нет | не задан | Docker и `npm start` | `1` запускает long polling, даже если у бота есть вебхук, и снимает этот вебхук. Без неё в такой ситуации бот не запускается (`"bot":"conflict"`), чтобы не отключить сервер, который работает через вебхук |
| `APP_PORT` | нет | `8080` | только Docker (`compose.yaml`) | Порт на хосте |
| `DOMAIN` | да, для профиля `https` | `localhost` | только Docker (профиль `https`) | Домен для Caddy. При значении по умолчанию Caddy выпускает локальный самоподписанный сертификат: так можно только проверить прокси, MAX такой адрес не примет. Для вебхука или своего адреса мини-приложения укажите свой домен. |
| `PORT` | нет | `8080` | только `npm start` | Порт сервера. В образе он задан в `Dockerfile` (`8080`) и из `.env` не передаётся: порт на хосте меняется через `APP_PORT` |
| `WEBAPP_DIST` | нет | `apps/webapp/dist` | только `npm start` | Каталог собранного мини-приложения. В образе он задан в `Dockerfile` (`/app/webapp`), менять не нужно |
| `MAX_API_BASE_URL` | нет | не задан | только тесты | Адрес имитации MAX API (`apps/bot/test/integration.mjs`) |

`.env.example` не содержит рабочих значений, `.env` исключён из git и из Docker-образа. Рабочий токен для проверки передаётся организаторам на служебном первом слайде презентации.

## 7. Зависимости

Версии зафиксированы в `package-lock.json` (один lock-файл на монорепозиторий, установка через `npm ci`). У всех зависимостей открытые лицензии (MIT, ISC, OFL-1.1, Apache-2.0).

- Node.js 20.19 или новее (образ собран на `node:24-alpine`, актуальной LTS-версии).
- Мини-приложение: `react` и `react-dom` 19.2.8 (эту версию требует UI-кит), `@maxhub/max-ui` 0.5.0 (MIT), `lucide-react` для иконок (ISC), `@fontsource/inter` для шрифта (OFL), Vite.
- Бот: `@maxhub/max-bot-api` 0.3.1 (MIT), сборка esbuild в один файл.
- Тесты и проверка типов: Vitest, jsdom, TypeScript.
- `tools/` (отдельный `package.json`, в образ не входит): `sharp` для чтения пикселей иллюстраций при расчёте зон нажатия.
- Скрипт MAX Bridge (`https://st.max.ru/js/max-web-app.js`) подключается с CDN платформы. Вне MAX приложение работает без него.

## 8. Внешние сервисы и интеграции

Решение состоит из двух частей:

- **Наша часть – запускается в Docker.** Это один контейнер: сервер бота, мини-приложение и проверка `/healthz`. Для HTTPS есть необязательный второй контейнер Caddy. Всё это собирается из репозитория командой `docker compose up --build` (раздел 4).
- **Мессенджер MAX – внешний сервис, в Docker его не поднять.** Бот получает и отправляет сообщения через серверы MAX, мини-приложение открывается внутри MAX. Скачать и запустить MAX у себя нельзя.

| Внешний сервис | Для чего нужен | Что нужно для проверки |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) – сервер MAX для ботов | Через него бот получает сообщения жителей и отправляет ответы | Токен бота. Рабочий токен – на служебном слайде презентации. Без токена бот выключен, мини-приложение работает. Для автотестов в проекте есть имитация этого сервера (`apps/bot/test/integration.mjs`) |
| MAX Bridge (`st.max.ru`) – скрипт MAX для мини-приложений | Даёт мини-приложению функции мессенджера: кнопку «Назад», вибрацию, запрос номера телефона, отправку в чат | Ничего: скрипт подключается сам. В обычном браузере его функций нет, и приложение использует замену (хранилище браузера, копирование текста, ввод номера вручную) |
| Корневой сертификат Минцифры | Серверы MAX защищены российским сертификатом «Russian Trusted Root CA», которому программы по умолчанию не доверяют. Без него бот не смог бы подключиться к MAX | Ничего: публичный сертификат (`deploy/russian_trusted_root_ca.pem`) уже встроен в сборку и используется только для запросов к MAX |
| Адрес с HTTPS для мини-приложения | MAX открывает мини-приложение только по защищённому адресу `https://…`. Адрес `localhost` для этого не подходит | Для рабочего бота адрес уже привязан к нему в MAX. Для своей копии подойдёт предпросмотр на GitHub Pages или свой домен с Caddy (профиль `https`). Боту в режиме long polling публичный адрес не нужен |

Возможности MAX, которые использует мини-приложение:

- нативная кнопка «Назад», которая закрывает шаги по одному;
- тактильный отклик при выборе, успехе и опасности;
- хранилище устройства для дома, отметок и истории, с запасным вариантом вне MAX и ограничением времени ожидания, чтобы экран не зависал;
- запрос контакта: номер телефона в обращение одной кнопкой;
- нативная отправка ответа или обращения в чат;
- открытие внешней ссылки на первоисточник нормы;
- подтверждение закрытия, если в черновике обращения есть несохранённые правки;
- параметр запуска: диплинк из бота сразу открывает нужную ситуацию дома.

Интеграций с ГИС ЖКХ и системами управляющих организаций нет. Справочник домов представляет собой снимок открытых данных на дату, указанную на экране. Заявки приложение не принимает, а готовит текст, который житель отправляет сам.

## 9. Работа с данными

Подробно в [docs/DATA.md](docs/DATA.md).

- Правила лежат в `packages/core/src/data/elements-*.ts`: объект → ситуации → ответ или уточняющий вопрос. У ответа указаны ответственные, однозначность (`clear` / `disputed`), основание (`norm` / `practice` / `contract`), пояснение, шаги, нормы и тип обращения. Ответ с основанием «практика» или «договор» всегда помечен как спорный случай и сопровождается шаблоном обращения, это проверяет тест.
- Нормы лежат в `packages/core/src/data/norms.ts` и пересказаны своими словами. 50 из 52 сверены по пунктам в действующей редакции, журнал сверки в [docs/NORMS.md](docs/NORMS.md).
- Дома и организации: `data/vichuga/*.csv` → `npm run data:import` → `packages/core/src/data/city.json`. Импорт проверяет данные и печатает расхождения источника. Формат файлов и столбцов – в [data/README.md](data/README.md).
- Персональные данные (ФИО, квартира, телефон для обращения, выбранный дом, отметки о доме) хранятся только на устройстве пользователя. Основное хранилище – хранилище устройства MAX. Если его нет (обычный браузер, веб-версия MAX) или оно не ответило за 1,5 секунды, данные сохраняются в хранилище браузера (localStorage). Копия в браузере появляется только в этом случае и удаляется при следующей удачной записи в хранилище MAX. Ключи начинаются с префикса `esli_chto:`. Префикс не даёт другим сайтам того же домена (например, другим проектам на `github.io`) прочитать или затереть эти данные. Длина полей обращения ограничена: ФИО до 120 символов, подъезд и квартира до 10, телефон до 20.
- Бот держит в памяти процесса только выбранный дом, счётчик запросов и отметку «ждёт адрес» после `/house`. Команда `/forget` удаляет всё это. Тексты сообщений не сохраняются. Дом из диплинка («Начать» по ссылке с домом) запоминается так же, как выбранный командой `/house`.
- Другой город подключается данными, без правки кода. В коде бота и мини-приложения нет адресов, организаций и телефонов конкретного города: названия, номера, городские службы и даже примеры адресов в подсказках берутся из справочника. Нужно скопировать образец `data/example/` в `data/<город>/`, заполнить четыре файла по [data/README.md](data/README.md) и выполнить `npm run data:import -- data/<город>`. Подключённый город запоминается, и дальше `npm run data:import` и CI работают с ним. Тесты проходят на справочнике любого города, а CI при каждом push подключает образец и прогоняет все проверки. Если реальных данных ещё нет и справочник тестовый, в `meta.json` ставится `"demo": true`, и тогда мини-приложение и бот сами помечают данные как демонстрационные. В справочнике Вичуги стоит `"demo": false`. Один запуск обслуживает один город (см. [docs/SCALING.md](docs/SCALING.md)).

## 11. Пошаговая проверка

### A. Мини-приложение без MAX (2 минуты)

1. `docker compose up --build` → <http://localhost:8080> (удобно в режиме телефона в инструментах разработчика) или сразу предпросмотр <https://annakotlova111.github.io/esli_chto/>.
2. «Выберите свой дом» → «Коровина 11». Появится карточка: УК «Жилищно-ремонтный участок №1», телефоны, диспетчерская. Снимите отметку «Лифт» и нажмите «Готово».

5. «Моя квартира» → «Газовая плита» → «Запах газа»: красный блок «Опасно» и кнопка «Позвонить 104».
6. Внизу «Срочно»: 112 и 104, список опасных ситуаций с прямым звонком, аварии в доме.

### B. Бот и мини-приложение в MAX

1. Откройте [@t527_hakaton_max_bot](https://max.ru/t527_hakaton_max_bot) или запустите свою копию со своим токеном `BOT_TOKEN` (не токеном рабочего бота, см. раздел 4) и подключите к ней мини-приложение по HTTPS-адресу.

## 13. Известные ограничения

- Справочник составлен по открытым данным на 23.09.2026. Организации могут сменить телефоны или договоры управления, поэтому на экране и в ответах бота указана дата и совет сверяться с квитанцией.
- Телефона домофонной компании нет: в городе их несколько, и открытые данные не говорят, какая обслуживает дом. Карточка подсказывает, что телефон указан на панели домофона или в квитанции. Лифтовой организации в городе нет, заявки по лифту принимает диспетчерская УК дома.
- В Вичуге две энергосбытовые компании. Показываются обе с пояснением, что своя указана в квитанции.
- Нет сведений об этажности и оборудовании домов, поэтому по умолчанию показываются все объекты, а лишнее житель отмечает сам.
- ИНН и отдельная диспетчерская есть в данных только у четырёх УК. У ТСЖ, ЖСК и ТСН в обращение подставляется название без ИНН, а аварии принимает правление.
- Расхождения источника: ул. Московская, 13 указана за двумя организациями; у ТСЖ «Ногинец-3» в карточке два дома, а в списке один; у ЖСК «Ногинец-4» в источнике нет номера дома, и в справочник он не попал.
- Выводы опираются на нормы и типовую практику, но договор управления конкретного дома может менять границы. Две ссылки (региональные законы о тишине и ПДД во дворах) указаны на уровне документа, и выводы по ним помечены как спорные.
- Бот хранит выбранный дом в памяти процесса, после перезапуска его нужно выбрать снова. В мини-приложении выбор хранится на устройстве.
- Рабочий бот работает одним процессом в режиме long polling, этот режим проверен и в настоящем MAX. Режим вебхука проверен только интеграционным тестом на имитации MAX API, с настоящим MAX он не запускался. Имитацию написала команда по документации MAX, она воспроизводит только те методы API, которые использует бот. Если какой-то метод в настоящем MAX ведёт себя иначе, тест этого не покажет. Запросы к MAX формирует официальная библиотека `@maxhub/max-bot-api`, это снижает такой риск.
- Нативные функции MAX проверены в мобильном клиенте 29.09.2026: открытие из бота, хранение выбранного дома, кнопка «Назад», номер из профиля MAX после разрешения, отправка через системное меню «Поделиться». Тактильный отклик работает на Android, на iPhone он не ощущается. В веб-версии MAX часть функций недоступна, и работают запасные варианты: хранилище браузера, копирование текста, ввод номера вручную.
- Иллюстрации плотные, на телефоне подписи мелкие. Поэтому есть кнопка «Крупнее» и полный список объектов под схемой.

## 14. Остановка и повторный запуск

```bash
docker compose down              # остановить и удалить контейнеры
docker compose up -d --build     # запустить снова в фоне
docker compose logs -f app       # журнал (JSON-строки)
```

Состояния на сервере нет, поэтому перезапуск безопасен: бот только забудет выбранные дома (см. раздел 13). После изменения `.env` выполните `docker compose up -d`. Остановить только HTTPS-прокси: `docker compose --profile https stop caddy`. Если локальную копию запускали с `FORCE_POLLING=1` на токене бота, который работал через вебхук, после её остановки вебхук сам не восстановится: перезапустите сервер, который работает в режиме вебхука.

Тесты проверят нормы, шаги, пометки спорности, экстренные номера и диплинки, а обход интерфейса откроет каждую ветку. После изменения данных выполните `npm run docs`: CI сверяет `docs/SCHEMES.md` и `docs/NORMS.md` с данными и падает при расхождении. Чтобы подключить другой город, заполните таблицы в `data/<город>/` по [data/README.md](data/README.md) и выполните `npm run data:import -- data/<город>`. Вернуть пилот: `npm run data:import -- data/vichuga`.
