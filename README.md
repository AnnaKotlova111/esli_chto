# «Если что» – кто отвечает, куда звонить и что делать, если в доме что-то сломалось

Мини-приложение и чат-бот в MAX для жителей многоквартирных домов. Житель нажимает на предмет на картинке дома или квартиры (или описывает проблему словами) и получает ответ: кто отвечает, телефон его организации, что делать по шагам и на какую норму это опирается. Спорные случаи помечены, для них готов текст обращения.

**Пилотный город – Вичуга (Ивановская область):** в справочнике 223 дома и 19 управляющих организаций, ТСЖ, ЖСК и ТСН из открытых данных. Правила ответственности – федеральные и работают для любого города.

> Сведения о домах и организациях – из открытых источников на 23.09.2026 (см. [docs/DATA.md](docs/DATA.md)). Контакты городских служб Вичуги (водоснабжение, теплоснабжение, энергосбыт, газ, ТКО, администрация, ГЖИ) подключены там же. Это справочная информация, а не юридическая консультация.

## 1. Назначение

Житель замечает поломку – течёт кран, не горит лампочка в подъезде, не работает лифт – и не знает, кто за это отвечает: управляющая организация, ресурсоснабжающая организация или он сам. Граница ответственности описана в нормах через элементы, невидимые глазом («первое отключающее устройство», «квартирный прибор учёта»), контакты разбросаны по квитанциям и доскам объявлений. Люди звонят не туда и получают отказы.

«Если что» решает одну задачу: **быстро определить, кто отвечает, и дать одно понятное действие – «Позвонить»**. Ответы не генерируются: для каждого объекта и ситуации заранее записано дерево правил со ссылкой на норму, поэтому один и тот же вопрос в одном доме всегда даёт один и тот же проверяемый ответ. Подробнее о проблеме и границах MVP – [docs/PROBLEM.md](docs/PROBLEM.md).

## 2. Основной пользовательский сценарий

**В мини-приложении**

1. Открыть бота в MAX → «Открыть карту дома».
2. «Выберите свой дом» → ввести адрес («Коровина 11») → карточка дома с организацией и телефонами. По желанию отметить, есть ли в доме лифт, газ, мусоропровод.
3. Вкладка «Наш дом» (схемы «Снаружи», «Подъезд», «Подвал и сети») или «Моя квартира» (план квартиры) → нажать на подпись объекта на картинке. Либо строка «Что случилось? Например: течёт кран».
4. Выбрать ситуацию → при необходимости ответить на 1–2 вопроса.
5. Ответ: блок «Срочно» с кнопкой звонка (если нужно) → кто отвечает и «Позвонить» → почему → что делать → на чём основано.
6. Спорный случай или нужен письменный запрос → «Составить обращение»: адрес дома, организация с ИНН и дата подставлены; текст можно поправить, скопировать или отправить в чат.

Отдельная кнопка «Срочно» внизу – все опасные и аварийные ситуации с прямым звонком: 112, 104 и аварийная служба дома.

**В боте:** написать «течёт кран» → выбрать ситуацию кнопкой → краткий ответ (кто отвечает, телефон, шаги, норма) → «Подробнее в приложении» открывает ту же ситуацию. `/house Коровина 11` – выбрать свой дом.

## 3. Состав и архитектура

Монорепозиторий на npm workspaces:

| Пакет | Роль |
|---|---|
| `packages/core` | Ядро: типы, правила ответственности (58 объектов, 129 ситуаций), справочник норм (51), справочник домов города, движок вопросов, поиск ситуаций и домов, шаблоны обращений, диплинки. Общее для бота и мини-приложения – ответы не расходятся. |
| `apps/webapp` | Мини-приложение: React 19 + официальный UI-кит MAX + MAX Bridge. Схемы-иллюстрации, карточки, вопросы, поиск, конструктор обращения. Работает без собственного API – всё собрано в статику. |
| `apps/bot` | Бот на официальной библиотеке MAX Bot API: разбор свободного текста, диалог кнопками, выбор дома по адресу, открытие мини-приложения по диплинку. Этот же процесс раздаёт статику мини-приложения и отвечает на `/healthz`. |
| `data/vichuga` | Исходные таблицы домов и организаций города (CSV) – из них собирается справочник. |
| `tools`, `scripts` | Инструменты разработки: определение зон нажатия по пикселям иллюстраций, импорт домов, генерация документации из данных. В образ не попадают. |

```
┌─────────────── MAX (мобильная / веб / десктоп) ────────────────┐
│  чат с ботом ── кнопка «Открыть карту дома» (диплинк) ──► мини-приложение │
└───────┬────────────────────────────────────────────┬──────────┘
        │ Bot API (вебхук / long polling)             │ HTTPS
        ▼                                             ▼
┌──────────────────── один контейнер (Node.js) ─────────────────────┐
│ apps/bot      бот + раздача статики + /healthz                      │
│ apps/webapp   собранная статика (без сервера данных)                │
│ packages/core правила, нормы, справочник домов Вичуги               │
└──────────────────────────────────────────────────────────────────┘
```

Собственного HTTP API с пользовательскими данными нет: мини-приложение – статика, бот работает поверх Bot API. Поэтому OpenAPI и `DATA-API.yaml` не требуются.

## 4. Запуск одной командой

Нужен Docker с Compose v2. Из корня репозитория – одна команда:

```bash
docker compose up --build
```

Файл `.env` для этого не нужен: у всех переменных есть значения по умолчанию. Он понадобится, чтобы включить бота (`cp .env.example .env` и вписать токен, см. ниже).

Откройте <http://localhost:8080> – мини-приложение работает сразу, бот без токена выключен. Проверка здоровья: <http://localhost:8080/healthz> →
`{"ok":true,"app":"Если что","version":"1.0.0","bot":"disabled","houses":223,"elements":58,"situations":129}`.

Поле `bot`: `disabled` – токена нет; `connecting` – идёт подключение к MAX; `polling` или `webhook` – бот работает; `error` – API MAX недоступен (сеть, сбой платформы, неверный токен). В этом случае сервер не останавливается: мини-приложение продолжает работать, подключение повторяется через 5, 10, 20… секунд (не реже раза в минуту), причина пишется в журнал.

В образ попадают только собранные файлы (multi-stage сборка на `node:24-alpine`); сборку и запуск контейнера с проверкой `/healthz` выполняет CI при каждом изменении.

### С ботом

1. Впишите в `.env` токен: `BOT_TOKEN=…` (в хакатоне выдаётся организаторами; вне его бота создают в business.max.ru → «Чат-боты»).
2. **Для разработки** оставьте `PUBLIC_URL` пустым – бот работает через long polling.
3. **Для продакшена** нужен публичный HTTPS-адрес (вебхук и мини-приложение работают только по HTTPS):
   ```bash
   # в .env: DOMAIN=esli-chto.example.org и PUBLIC_URL=https://esli-chto.example.org
   docker compose --profile https up -d --build
   ```
   Caddy получит сертификат автоматически; домен должен указывать на сервер, порты 80 и 443 открыты. Секрет вебхука задаётся в `WEBHOOK_SECRET`, а если он пуст – генерируется при запуске.
4. Подключите мини-приложение к боту: business.max.ru → чат-бот → ⋮ → «Настройки» → адрес мини-приложения. В хакатоне адрес передаётся организаторам через форму, и они привязывают его к боту.

### Предпросмотр мини-приложения

`.github/workflows/pages.yml` при каждом изменении ветки `main` собирает `apps/webapp` и публикует статику на GitHub Pages (Settings → Pages → Source: GitHub Actions). Бот при этом запускается отдельно и должен работать постоянно.

## 5. Переменные окружения

| Переменная | Обязательна | По умолчанию | Где действует | Назначение |
|---|---|---|---|---|
| `BOT_TOKEN` | нет | – | Docker и `npm start` | Токен бота. Без него запускается только мини-приложение. **Не коммитить.** |
| `BOT_USERNAME` | нет | из ответа MAX `/me` | Docker и `npm start` | Ник бота для кнопок открытия мини-приложения |
| `PUBLIC_URL` | нет | – | Docker и `npm start` | Публичный `https://…`. Задан – вебхук, пуст – long polling |
| `WEBHOOK_SECRET` | нет | случайный при запуске | Docker и `npm start` | Секрет, который MAX присылает в заголовке каждого события: 5–256 символов, латиница, цифры, `_` и `-`. Значение другого формата не используется – сервер пишет предупреждение и генерирует секрет сам |
| `WEBHOOK_PATH` | нет | `/max/webhook` | Docker и `npm start` | Путь вебхука |
| `RATE_LIMIT_PER_MINUTE` | нет | `20` | Docker и `npm start` | Сколько событий в минуту обрабатывается от одного пользователя |
| `MAX_API_TIMEOUT_MS` | нет | `60000` | Docker и `npm start` | Сколько ждать ответа MAX API; зависший запрос прерывается, пользователь получает сообщение об ошибке |
| `APP_PORT` | нет | `8080` | только Docker (`compose.yaml`) | Порт на хосте |
| `DOMAIN` | для профиля `https` | – | только Docker | Домен для Caddy |
| `PORT` | нет | `8080` | только `npm start` | Порт сервера. В контейнере всегда `8080`, наружу пробрасывается `APP_PORT` |
| `WEBAPP_DIST` | нет | `apps/webapp/dist`, в образе `/app/webapp` | только `npm start` | Каталог собранного мини-приложения |
| `MAX_API_BASE_URL` | нет | – | только тесты | Адрес имитации MAX API (`apps/bot/test/integration.mjs`) |

`.env.example` не содержит рабочих значений; `.env` исключён из git и из Docker-образа. Рабочий токен для проверки передаётся организаторам на служебном первом слайде презентации.

## 7. Зависимости

Версии зафиксированы в **`package-lock.json`** (один lock-файл на монорепозиторий, установка `npm ci`). Все зависимости – с открытыми лицензиями.

- Node.js ≥ 20.19 (образ – `node:24-alpine`, актуальный LTS).
- Мини-приложение: `react` / `react-dom` **19.2.8** (точно как требует UI-кит), `@maxhub/max-ui` **0.5.0** (MIT), `lucide-react` (ISC, иконки), `@fontsource/inter` (OFL, шрифт), Vite.
- Бот: `@maxhub/max-bot-api` **0.3.1** (MIT), сборка esbuild в один файл.
- Тесты и проверка типов: Vitest, jsdom, TypeScript.
- `tools/` (отдельный `package.json`, в образ не входит): `sharp` – чтение пикселей иллюстраций при расчёте зон нажатия.
- Скрипт MAX Bridge (`https://st.max.ru/js/max-web-app.js`) подключается с CDN платформы; вне MAX приложение работает без него.

| Сервис | Зачем | Можно ли поднять в Docker |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | сообщения бота | Нет – это сам мессенджер, нужен токен. Для автотестов есть имитация API (`apps/bot/test/integration.mjs`). |
| MAX Bridge (`st.max.ru`) | нативные функции мини-приложения | Нет; вне MAX работают запасные варианты. |
| Корневой сертификат Минцифры | API MAX подписан центром «Russian Trusted Root CA», которого нет в хранилищах Node.js и образа. Публичный сертификат (`deploy/russian_trusted_root_ca.pem`) встраивается в сборку бота и используется только для запросов к API MAX. | Уже учтено |
| Публичный домен и HTTPS | требование MAX к мини-приложению и вебхуку | Сертификат выпускает Caddy (профиль `https`), домен – внешний |

**Возможности MAX, которые использует мини-приложение:** нативная кнопка «Назад» (закрывает шаги по одному), тактильный отклик (выбор, успех, опасность), хранилище устройства (дом, отметки, история – с запасным вариантом вне MAX и таймаутом, чтобы экран не зависал), запрос контакта (номер телефона в обращение одной кнопкой), нативный шеринг (ответ или обращение – в чат), открытие внешней ссылки (первоисточник нормы), подтверждение закрытия (несохранённый черновик обращения), параметр запуска (диплинк из бота сразу открывает нужную ситуацию дома).

**Интеграций с ГИС ЖКХ и системами управляющих организаций нет.** Справочник домов – снимок открытых данных на дату, указанную на экране; заявки приложение не принимает, а готовит текст, который житель отправляет сам.

## 9. Работа с данными

Подробно – [docs/DATA.md](docs/DATA.md).

- **Правила** – `packages/core/src/data/elements-*.ts`: объект → ситуации → ответ или уточняющий вопрос. У ответа: ответственные, однозначность (`clear` / `disputed`), основание (`norm` / `practice` / `contract`), пояснение, шаги, нормы, тип обращения. Основание «практика» или «договор» – всегда «спорный случай» с шаблоном обращения (проверяется тестом).
- **Нормы** – `packages/core/src/data/norms.ts`, пересказ своими словами; 49 из 51 сверены по пунктам в действующей редакции, журнал сверки – [docs/NORMS.md](docs/NORMS.md).
- **Дома и организации** – `data/vichuga/*.csv` → `npm run data:import` → `packages/core/src/data/city.json`. Импорт проверяет данные и печатает расхождения источника.
- **Персональные данные** (ФИО, квартира, телефон для обращения, выбранный дом, отметки о доме) хранятся только на устройстве пользователя: в хранилище MAX, а вне MAX – в хранилище браузера под ключами с префиксом `esli_chto:`, чтобы их не могли прочитать или затереть другие сайты того же домена (например, другие проекты на `github.io`). Поля обращения ограничены по длине: ФИО – 120 символов, подъезд и квартира – 10, телефон – 20.
- **Бот** держит в памяти процесса только выбранный дом, счётчик запросов и отметку «ждёт адрес» (после `/house`); `/forget` удаляет всё это. Тексты сообщений не сохраняются. Дом из диплинка («Начать» по ссылке с домом) запоминается так же, как выбранный командой `/house`.
- **Другой город** подключается таблицами `data/<город>/` без правки кода. Если реальных данных ещё нет и справочник тестовый, в `meta.json` ставится `"demo": true` – тогда мини-приложение и бот сами помечают данные как демонстрационные (см. [docs/SCALING.md](docs/SCALING.md)).

## 11. Пошаговая проверка

### A. Мини-приложение без MAX (2 минуты)

1. `docker compose up --build` → <http://localhost:8080> (удобно в режиме телефона в инструментах разработчика) или сразу предпросмотр <https://annakotlova111.github.io/esli_chto/>.
2. «Выберите свой дом» → «Коровина 11» → карточка: УК «Жилищно-ремонтный участок №1», телефоны, диспетчерская. Снимите отметку «Лифт» → «Готово».
3. Схема «Снаружи»: подпись «Лифт» приглушена и помечена «нет в доме». Нажмите «Крыша» → «Течёт с крыши в квартиру или подъезд» → ответ: срочно, АДС с кнопкой «Позвонить», пояснение, шаги, нормы.
4. «Составить обращение» – в тексте адрес дома, УК с ИНН и дата. В поле «Телефон» введите `12345` – под полем появится подсказка «номер неполный». Нажмите «Отправить в чат» – приложение предупредит, что в тексте остались места в [квадратных скобках]: «Заполнить» переведёт к пустому полю ФИО, «Отправить всё равно» отправит как есть.
5. «Моя квартира» → «Газовая плита» → «Запах газа» → красный блок «Опасно» и «Позвонить 104».
6. Внизу «Срочно» → 112 и 104, список опасных ситуаций с прямым звонком, аварии в доме.
7. Строка «Что случилось?» → «засор» → ситуации из разных объектов.

### B. Бот и мини-приложение в MAX

1. Откройте [@t527_hakaton_max_bot](https://max.ru/t527_hakaton_max_bot) – или запустите свою копию с `BOT_TOKEN` и HTTPS (раздел 4) и подключите к ней мини-приложение.
2. «Начать» → приветствие; `/house Коровина 11` → бот запомнит дом и покажет телефоны УК.
3. «течёт кран» → кнопка ситуации → короткий ответ → «Подробнее в приложении» открывает ту же ситуацию того же дома (проверьте на телефоне и в веб-версии MAX).
4. `/urgent` – 112, 104, 102 и аварийная служба дома; `/houses` – список домов по страницам; `/forget` – бот забывает дом.

## 12. Примеры ожидаемого поведения

| Действие | Результат |
|---|---|
| «Перегорела лампочка на площадке», дом УК | Отвечает управляющая организация – УК «Жилищно-ремонтный участок №1», телефон; ПП № 491 п. 7, ПП № 290 п. 20 |
| То же, дом ТСЖ «Старатели» | «Отвечает ТСЖ», телефон правления |
| «Течёт труба под мойкой» → «до первого крана» | Управляющая организация и АДС, срочно (ПП № 491 п. 5) |
| То же → «после крана» | Ваша зона ответственности |
| То же → «крана нет или не закрывается» | Спорный случай: АДС, акт, шаблон обращения |
| «Прорыв трубы горячего водоснабжения» | «Опасно», сначала 112, затем аварийная служба |
| «Нет интернета во всём подъезде» | Оператор связи: сети связи не входят в общее имущество (ЖК РФ ст. 36 ч. 1) |
| «Вывезти старый диван» → «Мебель, бытовую технику…» | Региональный оператор ТКО: это крупногабаритные отходы (Правила обращения с ТКО, ПП № 293) |
| Дом не выбран, любая ситуация | Карточка УК предлагает «Выбрать дом» |
| Боту: «Ленинградская 6» | «Похоже на адрес. Сделать этот дом вашим?» – кнопка |
| Боту: «абракадабра» | «Не нашёл» + «Найти на схеме» и «Срочно» – без тупика |
| Боту: фото, стикер или файл без текста | «Я понимаю только текст…» + «Открыть карту дома» и «Срочно» |
| Сообщение боту в групповом чате | Бот молчит |
| «Начать» по ссылке с домом (`start=h_vch_pyatnitskiy_13`) | Карточка ТСЖ «Старатели»; дальше бот отвечает с телефонами этого дома |
| Обращение с незаполненными [полями] → «Отправить в чат» | Предупреждение «Остались незаполненные поля»: «Заполнить» или «Отправить всё равно» |
| Телефон `12345` в обращении | Подсказка «Похоже, номер неполный» – отправку не блокирует |
| API MAX недоступен при запуске | Мини-приложение работает, `/healthz` → `"bot":"error"`, бот подключится сам, когда API вернётся |
| API MAX не ответил на отправку сообщения | Через `MAX_API_TIMEOUT_MS` запрос прерывается, пользователь получает «Что-то пошло не так. Попробуйте ещё раз…» |

## 13. Известные ограничения

- **Справочник – снимок открытых данных на 23.09.2026.** Организации могут сменить телефоны или договоры управления; на экране и в ответах бота есть дата и совет сверяться с квитанцией.
- **Нет телефона домофонной компании**: в городе их несколько, и открытые данные не говорят, какая обслуживает дом, – карточка подсказывает, что телефон указан на панели домофона или в квитанции. Лифтовой организации в городе нет – заявки по лифту принимает диспетчерская УК дома.
- **Энергосбыт:** в Вичуге две сбытовые компании; показываются обе с пояснением, что своя – в квитанции.
- **Нет сведений об этажности и оборудовании домов** – по умолчанию показываются все объекты, лишнее житель отмечает сам.
- **Расхождения источника:** ул. Московская, 13 указана за двумя организациями; у ЖСК «Ногинец-4» в источнике нет номера дома (в справочник не попал).
- **Юридическая сторона:** вывод опирается на нормы и типовую практику; договор управления конкретного дома может менять границы. Две ссылки (региональные законы о тишине, ПДД во дворах) – на уровне документа, выводы по ним помечены как спорные.
- **Бот хранит выбранный дом в памяти процесса** – после перезапуска его нужно выбрать снова (в мини-приложении выбор хранится на устройстве).
- **Нативные функции MAX** (хранилище устройства, шеринг, запрос контакта, тактильный отклик) в веб-версии частично недоступны – работают запасные варианты. Проверены на имитации; окончательная проверка – в клиенте MAX с подключённым мини-приложением.
- **Иллюстрации** плотные: на телефоне подписи мелкие, поэтому есть кнопка «Крупнее» и полный список объектов под схемой.

## 14. Остановка и повторный запуск

```bash
docker compose down              # остановить и удалить контейнеры
docker compose up -d --build     # запустить снова в фоне
docker compose logs -f app       # журнал (JSON-строки)
```

Состояния на сервере нет – перезапуск безопасен (бот только забудет выбранные дома, см. раздел 13). После изменения `.env` выполните `docker compose up -d`. Остановить только HTTPS-прокси: `docker compose --profile https stop caddy`.

## 15. Разработка и тесты

```bash
npm ci
npm run dev:web          # мини-приложение на http://localhost:5173
npm run dev:bot          # собрать и запустить бота с .env из корня; статику отдаёт из apps/webapp/dist (после npm run build)
npm run build            # сборка мини-приложения и бота
npm start                # запуск собранного сервера
npm run data:import      # пересобрать справочник домов из data/vichuga/*.csv
```

Добавить ситуацию – дописать данные в `packages/core/src/data/elements-*.ts`: тесты проверят нормы, шаги, пометки спорности, экстренные номера и диплинки, а обход интерфейса откроет каждую ветку. Подключить другой город – положить таблицы в `data/<город>/` и выполнить импорт.
